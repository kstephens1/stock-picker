# Development Instructions for Copilot

When working on this StockPicker project, follow these guidelines:

## Before Writing Code
1. Read the existing codebase structure
2. Check similar implementations in the codebase
3. Review the test files to understand expected behavior
4. Ask clarifying questions about requirements

## Code Quality
- All code must be well-commented and self-documenting
- Follow the existing code style in each directory
- Use consistent naming conventions (camelCase for JS)
- Keep functions focused and testable

## Testing Requirements
Every PR must include:
- ✅ Unit tests for new backend logic
- ✅ React component tests for new UI
- ✅ E2E tests if user workflows are affected
- ✅ All existing tests still pass

## Git & PR Best Practices
- Use conventional commit messages:
  - `feat:` for new features
  - `fix:` for bug fixes
  - `test:` for test additions
  - `docs:` for documentation
  - `refactor:` for code restructuring
  
- Keep PRs focused on one concern
- Provide clear PR descriptions
- Reference related issues with `Closes #123`

## Environment Setup
- `.env.example` files document required variables
- Production secrets stored in GitHub Environment Secrets
- Never hardcode API keys or credentials
- Test with environment variables from `.env`

## Async Operations
- Always use try-catch for async/await
- Handle rejection cases in promises
- Use proper error messages for debugging

## Performance
- Monitor for N+1 database queries
- Cache static data appropriately
- Minimize unnecessary re-renders in React

## Mobile-First Context
- This repo uses Copilot Workspace for GitHub Mobile
- Issues assigned to @copilot will be autonomously implemented
- Plan generation happens before code changes
- Tests run in CI automatically

## Documentation
- Update README.md for significant changes
- Add JSDoc comments for exported functions
- Include examples in complex logic
- Document any new environment variables

## If Something Breaks
- Check GitHub Actions logs for CI failures
- Review test output for specific failures
- Verify environment configuration
- Check for missing dependencies

---
Keep code quality high and tests passing. Good luck!
