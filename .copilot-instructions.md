# Copilot Instructions for StockPicker

## Project Overview
StockPicker is a full-stack MERN application for stock market analysis with a React frontend (Bootstrap), Node.js/Express backend, and SQLite database deployed on Firebase and Google Compute Engine.

## Technology Stack
- **Frontend**: React 18 (CRA), Bootstrap 5, React Router
- **Backend**: Node.js 18, Express.js, SQLite3
- **Testing**: Jest (unit), Playwright (E2E)
- **Deployment**: Firebase Hosting (frontend), Google Compute Engine (backend)
- **CI/CD**: GitHub Actions

## Key Directories
- `/client` - React frontend (port 3000 in dev)
- `/server` - Express backend (port 4000 in dev)
- `/e2e` - Playwright E2E tests
- `/scripts` - Deployment scripts

## Important Files
- `client/src/App.js` - Main React component
- `server/src/index.js` - Express server entry point
- `server/src/stockPriceService.js` - Core business logic
- `client/src/config/auth.js` - Authentication (fixed: keith/ferret)
- `firebase.json` - Firebase configuration

## Development Workflow
```bash
npm install:all       # Install all dependencies
npm run dev           # Start both server and client
npm run test:unit     # Run unit tests
npm run test:e2e      # Run E2E tests
npm run build         # Build for production
npm run deploy:prod   # Deploy to production
```

## Code Standards
1. **React**: Use functional components with hooks
2. **Backend**: Follow Express middleware patterns
3. **Testing**: Require tests for all new features
4. **Commits**: Use conventional commits (feat:, fix:, docs:, test:)
5. **Error Handling**: Always include try-catch in async operations
6. **Authentication**: Use MD5 hash comparison in auth.js

## When Creating/Modifying Code
1. **Always import dependencies at top of file**
2. **Update tests before implementation** (TDD approach preferred)
3. **Run tests locally**: `npm run test:unit && npm run test:e2e`
4. **Update README.md if adding new scripts or commands**
5. **Add JSDoc comments** to exported functions
6. **Handle CORS properly** in Express middleware

## Database Changes
- SQLite3 is used directly (no ORM)
- Database file location: `/var/lib/stockpicker/stocks.db` (production)
- Ensure migrations are idempotent
- Test with fresh database state

## Firebase & GCP Secrets
- Never commit credentials or API keys
- Use GitHub Environment Secrets for production
- Required secrets stored in: `.env` (local only)
- Reference: `deploy/backend.env.example`

## Pull Request Template
When generating PRs, include:
1. Description of changes
2. Testing approach (unit test improvements, E2E coverage)
3. Breaking changes (if any)
4. Migration steps (if needed)
5. Screenshots (for UI changes)

- Use GitHub App's native PR reviewer for feedback

## Common Tasks

### Adding a New API Endpoint
1. Add route to `server/src/index.js`
2. Extract logic to `server/src/stockPriceService.js`
3. Add unit tests in `server/__tests__/`
4. Update `client/src/App.js` to call the endpoint
5. Add E2E test in `e2e/tests/app.spec.js`

### Frontend UI Changes
1. Modify component in `client/src/`
2. Add unit tests using React Testing Library
3. Update E2E test if user flow changes
4. Ensure Bootstrap classes are used for styling

### Deployment Issues
1. Check GitHub Actions logs
2. Verify environment secrets are set
3. Run smoke tests: `npm run smoke:prod`
4. Check VM systemd service: `sudo systemctl status stock-picker`

## Performance Considerations
- Client: Use React.memo for expensive components
- Backend: Cache stock price queries when possible
- Database: Index frequently queried columns
- E2E tests: Keep timeout configurations reasonable

## Accessibility & Best Practices
- Use semantic HTML in React components
- Ensure Bootstrap components are accessible
- Write descriptive error messages
- Log errors appropriately (not sensitive data)
- Use environment variables for configuration
